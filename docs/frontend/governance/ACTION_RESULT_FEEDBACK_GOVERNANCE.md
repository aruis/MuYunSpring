# 动作结果与反馈专项治理

本文约束平台动作执行后的业务结果语义、前端反馈渲染和动静一体接入方式。目标是让后端表达稳定业务事实，让前端统一消费和渲染，避免具体页面散落提示样式、成功文案和刷新逻辑。

## 问题

当前部分页面直接调用 `presentPlatformMessage(message, context)`。该门面本身是通用提示入口，如果调用方没有显式声明成功语义，成功操作可能被渲染成错误样式，例如红色边框、警告图标或过强的中心提示。

这类问题不应通过后端返回 UI tone 解决。后端不能耦合前端位置、颜色、图标、弹层形态等 UI 表现；但后端可以且应该表达动作完成、无变化、部分完成、被阻断等业务结果语义。

## 边界

后端职责：

1. 执行业务动作并保证事务一致性。
2. 返回稳定的业务结果，例如完成、无变化、部分完成或阻断原因。
3. 返回业务文案或文案 key，供前端作为默认反馈内容。
4. 不返回 UI 渲染语义，例如 toast 位置、颜色、图标、弹窗类型。

前端职责：

1. 根据后端业务结果和前端交互上下文决定展示方式。
2. 统一成功、校验、权限、错误和后台任务反馈的渲染出口。
3. 避免页面直接拼装样式语义或重复书写 `tone: 'success'` 样板。
4. 优先通过通用动作执行器消费静态和动态动作，减少页面硬编码。

## 业务结果语义

平台动作响应可以逐步沉淀为业务结果模型。字段命名需避免 UI 倾向，建议使用 `outcome` 或等价业务字段。

建议语义：

| 语义 | 含义 | 前端默认反馈 |
| --- | --- | --- |
| `completed` | 动作已完成并产生预期结果 | 成功轻提示 |
| `noop` | 请求合法，但目标状态已经满足或无可变更数据 | 中性轻提示或静默 |
| `partial` | 动作部分完成，存在未处理项 | 警示提示，可提供详情 |
| `blocked` | 动作被业务规则阻断 | 错误或警示提示 |

短期不要求所有接口立即改响应结构。现有 `message` 仍可保留为业务默认文案，但前端不能仅凭 `message` 推断 UI tone。

## 前端门面

前端应提供明确门面，减少生硬样板：

```ts
presentPlatformSuccess(message, context)
presentPlatformNotice(message, context)
presentPlatformError(cause, context)
```

`presentPlatformMessage` 可保留为底层兼容入口，但业务页面不应优先直接使用它表达成功操作。成功动作应调用 `presentPlatformSuccess`，或由通用 action executor 根据动作结果统一展示。

成功提示默认应是轻量反馈，例如右上角或顶部非阻断 toast。中心位置、modal 或强警示样式应保留给阻断性错误、权限失败、冲突确认或需要用户明确处理的状态。

## 动作执行器

静态和动态页面应逐步统一到动作执行器：

```text
页面触发动作
动作执行器读取 action descriptor
执行 HTTP 请求
解析业务结果 outcome/message
统一展示反馈
统一刷新列表、详情或局部状态
```

具体页面只声明动作入口、业务参数和必要的局部状态更新。页面不应重复处理成功提示、错误提示、默认文案和通用刷新策略。

## 后端描述能力

后端可在动作描述或响应中提供业务语义，不提供 UI 语义。

可演进方向：

1. `WebCountResponse` 等动作响应增加业务结果字段，例如 `outcome`。
2. `@CustomActionEndpoint` 或动作 descriptor 声明默认成功文案，例如 `successMessage`。
3. 动态动作元数据声明动作完成后的默认刷新目标，例如列表、详情、当前记录或静默。
4. 后端只表达业务完成事实和默认业务文案，前端根据统一策略映射到具体 UI。

## 分阶段治理

### 短期

1. 增加 `presentPlatformSuccess` 门面。
2. 将成功操作从 `presentPlatformMessage(..., { tone: 'success' })` 收敛到成功门面。
3. 保留错误、校验和授权提示的明确分流。
4. 用契约测试约束关键页面成功动作不能落回错误样式。

### 中期

1. 动作执行器统一消费静态 record action 和局部业务 action。
2. 动作响应或 descriptor 引入 `outcome`、默认成功文案和刷新建议。
3. 职员账户创建、移除等自定义动作接入统一执行器。
4. 页面只保留业务局部状态，不保留通用反馈样板。

### 长期

1. 静态 Java action、动态 action 和 UI action block 使用同一套结果语义。
2. 前端根据 action descriptor 和 outcome 自动完成反馈、刷新和错误出口。
3. 业务模块只声明业务动作，不重复实现平台反馈流程。

## 验收口径

1. 成功动作默认显示成功轻提示，不出现错误色、警告图标或阻断式中心提示。
2. 后端响应和动作描述不包含前端 UI 样式字段。
3. 页面代码不直接散落 `tone: 'success'` 样板。
4. 同类动作在静态页面和动态页面中反馈一致。
5. 删除、创建、启停、排序、局部编辑等标准动作可由统一执行器处理反馈和刷新。
