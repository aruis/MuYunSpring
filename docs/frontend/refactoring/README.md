# 前端改造方案

本目录记录 MuYunSpring 前端已经确认的改造目标、边界、迁移方案和验收标准，作为
`muyun-web` 持续演进的专题入口。

这里不记录讨论流水、临时探索结论或尚未进入决策的设想。一个改造专题只有在目标、范围、
关键取舍和验收口径已经明确后才进入本目录；未确认的方向继续按
[前端技术架构](../TECHNICAL_ARCHITECTURE.md)和
[前端设计原则](../DESIGN_PRINCIPLES.md)判断，不提前创建空方案。

## 改造原则

1. 改造必须服务于已经确认的平台边界、开发体验或质量契约，不为工具统一本身制造迁移。
2. 方案同时说明收益、成本、非目标和验收方式，不用笼统的“升级”或“现代化”替代技术判断。
3. 改造不得绕过 MuYun 的动静一体路线、前端分层和 UI adapter 边界。
4. 实施阶段应保持生产行为和公开消费契约稳定，确需改变时必须在对应专题中显式说明。
5. 专题完成后，将仍有长期约束价值的结论回收到正式架构文档；仅服务迁移过程的内容应删除，
   避免本目录长期保存已经失效的执行方案。
