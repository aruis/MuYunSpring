# 角色授权设计

本文固化身份权限专题的角色授权设计。当前代码按本文收口；未上线阶段不保留旧模型兼容迁移路线。

## 核心取舍

角色授权只保留两条主链路：

| 授权层级 | 文案 | 授权主体 | 数据范围 |
| --- | --- | --- | --- |
| `ACCOUNT` | 账号角色 | 用户账号 | 不配置组织、部门、本人、任职等数据范围 |
| `EMPLOYMENT` | 任职角色 | 职员任职 | 可配置动作数据范围 |

账号角色用于登录身份级权限，例如平台管理员、租户管理员、机构管理员、运维账号或服务账号。这类账号不一定存在对应职员，不应为了授权强行创建职员。

任职角色用于组织职责级权限。兼职、多部门任职、岗位模板和部门数据范围都应落到具体任职事实上解释。任职角色的上下文来自该任职的机构、部门和任职 ID。

不再提供职员级角色授权。职员身份是人员主数据，不表达具体职责上下文；职员本人相关的业务能力应通过规则或数据权限字段表达，例如 `authEmployeeId` 或后续稳定的本人归属字段，而不是给职员直接绑定角色。

## 目标模型

`Role` 仍是唯一角色定义表，不新增账号角色表。角色通过授权层级区分账号角色和任职角色：

```text
Role
  assignmentType = ACCOUNT / EMPLOYMENT
  ownerScopeType = PLATFORM / TENANT / ORGANIZATION
  ownerScopeId = null / tenantId / organizationId
  ownerScopeKey = platform / tenant:{tenantId} / organization:{organizationId}
  sharePolicy = PRIVATE / OWNER_AND_CHILDREN / TENANT / PLATFORM
```

`ownerScopeType` 和 `ownerScopeId` 表达角色定义归属，也就是角色由平台、租户或机构维护。`ownerScopeKey` 是服务端派生的非空归属键，用于稳定唯一约束，不作为业务自由字段。`sharePolicy` 表达角色定义的共享范围：平台角色可平台私有或全局公开，租户角色可租户私有或租户内公开，机构角色可机构私有或本机构及下级机构公开。

角色定义归属不等于授权生效上下文。账号管理员的管理作用域仍落在 `AccountRoleGrant.managementScopeType + managementScopeId`，任职角色的数据范围上下文仍来自 `EmploymentRoleGrant.employeePositionId` 指向的任职机构和部门。

账号角色和任职角色的授权事实分表承载：

| 授权事实 | 说明 | 核心字段 |
| --- | --- | --- |
| `AccountRoleGrant` | 账号角色授权事实，只用于用户账号绑定账号角色。 | `roleId`、`userId`、`managementScopeType`、`managementScopeId`、`enabled` |
| `EmploymentRoleGrant` | 任职角色授权事实，只用于职员任职绑定任职角色、角色组或数据授权角色。 | `roleId`、`employeePositionId`、`enabled` |

不再使用一张通用 `RoleGrant(subjectType, subjectId)` 表表达全部授权关系。账号授权和任职授权的字段、上下文和校验规则不同，拆分后更容易解释、审计和维护。

推荐 Web 入口按授权事实拆分，避免继续暴露通用主体类型：

```text
POST /iam.role/{roleId}/account-grants
POST /iam.role/{roleId}/employment-grants
```

也可以在具体主体页面提供面向主体的子资源入口：

```text
POST /iam.user/{userId}/roles
POST /iam.employee/{employeeId}/positions/{positionId}/roles
```

## 角色类型

角色类型保留为角色能力形态，不再承担授权主体选择：

| 类型 | 说明 |
| --- | --- |
| 普通角色 | 可配置动作授权。按授权层级分为账号角色或任职角色。 |
| 角色组 | 任职级角色包，只能包含任职级普通角色和最多一个数据授权角色，只能授予任职。 |
| 数据授权角色 | 任职级数据范围模板，只为选择“继承数据授权”的动作提供兜底数据范围。 |
| 系统角色 | 平台内部托管角色形态。是否可授予账号或任职仍由授权层级决定。 |

角色组不是账号管理员权限打包工具。账号级角色通常数量少、语义强，直接授予账号更便于审计。

## 角色组规则

角色组锁定为任职级能力：

1. 角色组只能授予职员任职。
2. 角色组只能包含任职级普通角色。
3. 角色组最多包含一个数据授权角色。
4. 角色组本身不配置动作授权和数据范围。
5. 当前不建设角色组嵌套。

授予角色组时，运行态展开成员角色。成员角色的授权来源上下文仍是被授予的任职。

## 数据授权角色

数据授权角色用于降低基础权限配置成本，但不直接提供动作资格。

数据授权角色规则：

1. 只能是任职级。
2. 只能授予职员任职。
3. 不配置业务动作资格。
4. 只配置可被继承的数据范围模板。
5. 一个任职直接或通过角色组最多生效一个数据授权角色。

数据授权角色不是账号级通配权限，也不是额外放宽机制。它只在动作授权明确选择“继承数据授权”时参与计算。

## 数据范围策略

账号角色不配置组织、部门、本人、任职等数据范围。账号角色仍受租户边界、系统态边界和动作授权约束。租户管理员这类账号级权限如果需要管理当前租户全部数据，应由账号角色自身语义和动作授权表达为当前租户管理权限，而不是通过部门或任职数据范围表达。

任职角色的动作授权在动作开启数据权限时必须选择一种数据范围策略：

| 策略类别 | 说明 |
| --- | --- |
| 具体范围 | 例如本人、本机构、本机构及下级、本部门、本部门及下级、引用依赖等。 |
| 继承数据授权 | 本角色不直接指定范围，运行时从当前任职的生效数据授权角色解析范围。 |
| 无数据权限 | 明确拒绝该动作的数据范围，不会被数据授权角色补齐。 |

“继承数据授权”是显式策略，不等同于空值或默认值。建议代码值使用 `INHERIT_DATA_GRANT`，后台文案统一为“继承数据授权”。

运行优先级：

1. 动作未开启数据权限：不显示也不保存数据范围。
2. 动作开启数据权限且选择具体范围：使用动作授权自身范围。
3. 动作开启数据权限且选择无数据权限：拒绝该动作的数据访问范围。
4. 动作开启数据权限且选择继承数据授权：查找当前任职的生效数据授权角色。
5. 未找到可用数据授权角色时，按配置错误处理，不自动退回全量或最小范围。

数据授权角色不会与动作自身范围取并集，也不会把显式配置的数据范围悄悄放宽。

## 账号管理员

平台超级管理员、租户管理员和机构管理员都属于账号级身份，不要求存在对应职员或任职。

| 管理员 | 表达方式 | 作用域 |
| --- | --- | --- |
| 平台超级管理员 | 系统账号或账号级系统角色授权。 | 平台级，不归属普通租户。 |
| 租户管理员 | `AccountRoleGrant` 绑定 `tenant.admin` 账号角色。 | `managementScopeType = TENANT`，`managementScopeId = tenantId` |
| 机构管理员 | `AccountRoleGrant` 绑定 `organization.admin` 账号角色。 | `managementScopeType = ORGANIZATION`，`managementScopeId = organizationId` |

管理作用域不是通用数据范围，也不等同于任职角色的数据权限。账号角色不配置动作级组织、部门、本人或任职数据范围；租户管理员和机构管理员的治理边界由账号角色语义和授权事实上的管理作用域解释。

账号表只表达登录账号事实，不承载管理员开关、管理员类型或作用域字段。管理员身份必须落到 `AccountRoleGrant`，这样才能支持审计、启停、换人、多管理员和系统托管治理。

新增租户或机构时，可以由业务开通动作创建默认管理员账号和授权事实：

```text
创建租户
  -> 创建租户管理员账号
  -> 插入 AccountRoleGrant(role = tenant.admin, scope = TENANT:tenantId)

创建机构
  -> 创建机构管理员账号
  -> 插入 AccountRoleGrant(role = organization.admin, scope = ORGANIZATION:organizationId)
```

默认管理员账号和默认授权可以标记为系统托管，但权限判断仍读取账号角色授权事实，不把管理员身份写死在程序分支或账号表字段中。

## 权限生效链路

普通登录用户的权限生效链路：

```text
UserAccount
  -> 账号角色
  -> EmployeeAccount
  -> Employee
  -> EmployeePosition
  -> 任职角色 / 角色组 / 数据授权角色
```

动作资格来自账号角色和任职角色。账号角色只提供身份级动作权限；任职角色提供组织职责级动作权限。数据授权角色只为任职角色中选择“继承数据授权”的动作提供数据范围。

数据范围解释必须保留授权来源上下文。任职角色和角色组展开后的成员角色，都按被授予任职的机构、部门和任职 ID 解释相对范围。

## 不做事项

1. 不提供职员级角色授权。
2. 不提供账号级数据授权角色。
3. 不允许账号绑定角色组。
4. 不允许角色组混合账号角色和任职角色。
5. 不让多个数据授权角色叠加放宽最终数据范围。
6. 不把“继承数据授权”作为空值、系统默认或隐式回退。
